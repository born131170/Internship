# PersonaScope

Поведенческий анализ видео: локальный движок MediaPipe измеряет мимику, позу, руки и речь по кадрам,
детерминированный психометрический слой переводит измерения в шкалы, внешняя LLM пишет текстовую
интерпретацию. Все числа считаются локально и воспроизводимо — модель не имеет права их менять.

```
видео ─► MediaPipe (лицо/поза/руки) + аудио-просодия ─► metrics.jsonl (по кадрам)
      ─► паттерны P01–P14 ─► эпизоды со скрин-кадрами
      ─► psychometrics.py: LR-агрегация Big Five, CI, композиты ─► summary.json
      ─► scoring.py: единый набор чисел для UI, LLM и экспорта
      ─► LLM (опционально): текстовая интерпретация + цитаты эпизодов
```

## Честный статус научной валидности

Это измерительный инструмент, а не диагностика. Что подтверждено, а что нет — зафиксировано в коде
(`psychometrics.MODEL_VALIDITY`) и выводится в интерфейсе:

| Модель | Статус по видео | Как выдаётся |
|---|---|---|
| Big Five (OCEAN) | частичная валидность невербальных маркеров (r ≈ 0.1–0.35) | LR-агрегация по индикаторам, 95 % интервал, кадры-доказательства |
| HEXACO | слабая | производные от OCEAN, помечены как низкая поддержка |
| Temperament | низкая | композит «энергия × стабильность» |
| MBTI | **не валидирован** | производные оси (S/N копируется с Openness, T/F — с Agreeableness), в ответе стоят предупреждения |
| Эннеаграмма | **не валидирована** | `status: not_assessed`, тип не выводится |
| PID-5 (DSM-5) | **неприменим** по видео | `status: not_assessed` |
| Правдивость | недиагностична (d ≈ 0.06–0.2, точность ≈ 54 %) | приор нагрузки/арузала с явной формулировкой «не различимо», НЕ вероятность лжи |

## Быстрый старт

Требования: Python 3.9–3.13 (проверено на 3.13.1 + mediapipe 1.0.0), Microsoft Visual C++ Redistributable
2015–2022 (x64) на Windows. Системные OpenGL-библиотеки **нужны только на headless Linux** — на Windows и
macOS их не существует, ставить `libEGL`/`apt-get` там нечего.

```bat
:: Windows
cd C:\PersonaScope
python run.py
```

```bash
# Linux / macOS
cd ~/PersonaScope
python run.py
```

`run.py` сам проверит зависимости (и доустановит их из `requirements.txt`, если чего-то нет), на headless
Linux при необходимости поставит mesa-пакеты, поднимет сервер и напечатает адрес.

Вручную, если автоустановка не сработала:

```bat
py -3.13 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python run.py
```

## Настройка LLM (опционально)

Локальный анализ работает без интернета и без ключа. LLM нужна только для текстовой интерпретации.

Ключ можно задать тремя способами (приоритет сверху вниз):

1. **Переменные окружения:** `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TEMPERATURE`, `LLM_TIMEOUT`.
2. **Файл `.env.local`** в корне проекта (в `.gitignore`, в git не попадёт):

   ```ini
   LLM_BASE_URL=https://api.example.com/v1
   LLM_API_KEY=sk-...
   LLM_MODEL=my-model
   LLM_TEMPERATURE=0.3
   LLM_TIMEOUT=180
   ```
3. **Интерфейс:** вкладка «Настройки LLM» → сохраняется в `data/llm_config.json` (этот файл тоже
   в `.gitignore`, потому что содержит ключ).

Кнопка «Проверить» делает реальный запрос; вкладка «Промпт» показывает RAW-ответ модели. Если модель
вернула не-JSON, результаты **не применяются** — в интерфейсе появится предупреждение и RAW для разбора.

## Что именно измеряется

### Паттерны P01–P14

Пороги живут в `pipeline.PATTERN_DEFS` и калиброваны на референсных прогонах; значения и обоснование
попадают в `summary["calibration"]` каждого видео, чтобы их можно было проверить, а не принимать на веру.

| Код | Что это | Порог / определение |
|---|---|---|
| P01 | моргание | `eyeBlink > 0.5`, события с рефрактерностью 0.2 c (Doughty 1989) |
| P02 | кивок при слушании | `|pc| > 0.08` |
| P03 | движения головы | `|yc| + |pc| > 0.03` |
| P04 / P05 | жестовый эпизод / амплитуда | `hand_speed > 0.03` / `> 0.1` |
| P06 | рука около лица (адаптор) | кончик пальца в боксе лица ×1.30 **или** 3D-дистанция запястье→голова < 0.8 ширин плеч, и кисть детектирована |
| P07 | мелкая моторика (fidgeting) | `hand_speed > 0.01` |
| P08 | положение рук | `aperture < 0.8` |
| P09 | смена позы | `menergy > 0.02` |
| P10 | улыбка | `smile > 0.4` |
| P10D | Duchenne-улыбка (AU6+AU12) | `smile > 0.35` и AU6 > 0.15, где AU6 = max(`cheekRaise`, геометрия глаза) |
| P11 | напряжение мимики (AU4/AU24) | `browDown > 0.3` или `press > 0.2` |
| P12 | отведение взгляда | `|yaw − медиана| > 25°` (только yaw; кивок по pitch не учитывается) |
| P13 | вокализация | флаг речи из VAD |
| P14 | пауза в речи | тишина 0.5–3 c, начавшаяся не позже 5 c после речи |
| `touch` | **касание лица рукой** | расстояние от точек кисти до меша лица в единицах межзрачкового расстояния, фолбэк — запястье позы при достаточной видимости; эпизод — от долей секунды со склейкой коротких разрывов. Отдельный канал и отдельный детектор, а не P06 |

Пороги паттернов не «магические»: они вынесены в константы `pipeline.py`, а их значения и
обоснование попадают в `summary["calibration"]` каждого прогона. Ниже — что и почему менялось по
итогам проверок на демонстрационных роликах с разметкой:

* **P10D** раньше опирался на blendshape `cheekRaise`, который в mediapipe 1.0.0 приходит нулевым
  почти во всех кадрах, поэтому паттерн практически не срабатывал. Теперь AU6 берётся как максимум из
  blendshape и геометрической оценки по точкам глаза (одна реализация — `pipeline.ocu_from_landmarks`).
* **P12** с прежним порогом срабатывал на единичных кадрах и не различал отведение взгляда и кивок.
  Теперь учитывается только yaw, порог приведён к измеримому диапазону, pitch исключён.
* **P14** считался активным почти на всём видео, потому что «паузой» становилась любая тишина.
  Теперь учитывается только пауза внутри речевого контекста.
* **Касание лица рукой** определялось как «кисть детектирована **и** два из трёх грубых признаков»;
  каждый признак сам по себе редкий, а их пересечение оставляло около процента кадров — поэтому
  строгий режим поиска не находил ничего. Теперь это геометрия: расстояние от точек кисти до меша лица,
  нормированное на межзрачковое расстояние, с фолбэком по запястью позы. Фолбэк считается только при
  достаточной видимости запястья: когда рука вне кадра, модель позы отдаёт правдоподобную, но неверную
  точку, и «касание» появлялось там, где ладоней в кадре нет.

Работа над детекторами продолжается: калибровка выполняется перебором по разметке (см. `tools/`),
каждое изменение порога проверяется на одних и тех же роликах, а результаты складываются в отчёты
рядом с данными.

### Поиск эпизодов по цифровому слепку (`snapshots.py`)

Слепок — это окно жеста, оцифрованное по каналам метрик. Поиск устроен так:

1. **Кандидаты.** В обычном режиме — эпизоды выбранного паттерна; в строгом режиме «касание лица» —
   геометрические эпизоды касания из `pipeline.touch_spans`. Длинные интервалы режутся на окна длиной
   со слепок (`MAX_DUR_RATIO = 2`): раньше кандидат «00:17–01:10» (53 c при слепке 3 c) обыгрывал
   реальные короткие эпизоды.
2. **Выбор паттерна** — по специфичности: доля паттерна в окне слепка делится на его долю во всём видео
   (lift). Так P03/P07, активные почти везде, не вытесняют P06/P04.
3. **Сравнение.** Каналы касания (`touch`, `twrist`) сравниваются **в абсолютных единицах** — важна
   реальная близость руки к лицу; остальные — по форме z-нормированной кривой (0.3·евклид + 0.7·DTW).
4. **Порог «совпадение / фон».** Считается нулевое распределение — те же расстояния на 120 случайных
   окнах той же длины; порог = 20-й процентиль. Ниже порога — совпадения, выше — фон, и поиск честно
   отвечает «не найдено». Раньше всегда возвращался top-K, поэтому на шуме интерфейс показывал
   десятки «находок».
5. **Поиск в чужом видео** не пересчитывает окно слепка по таймкодам источника (они в целевом видео
   ничего не значат): доли паттернов и доля касания берутся из самого слепка.

Замер на разметке владельца проекта (скрипты `tools/eval_touch.py` и `tools/eval_search.py`):
строгий режим касания не даёт ложных находок — все найденные эпизоды попадают в размеченные окна,
а окна «рука проходит рядом» (поправляет волосы, проносит ладони мимо лица) детектор не считает
касанием. Обычный режим поиска заметно менее точен. Чувствительность ограничена качеством шаблона
и тем, что кисть не всегда видна — это следующий этап работы, см. «Известные ограничения».

### Психометрический слой (`psychometrics.py`)

Поведенческие переменные (частота моргания, Duchenne-доля, доля негативной экспрессии, мобильность головы,
темп речи, паузы, вариабельность F0, кинетизм…) превращаются в шкалы через карту отношений правдоподобия:

* каждый индикатор даёт `LR = P(индикатор | высокая черта) / P(индикатор | низкая черта)` в диапазоне `[1/8, 8]`;
* веса зависят от уровня доказательности (`strong`/`moderate`/`weak` = 1.0/0.6/0.3);
* агрегация — нормированная сумма логарифмов LR, перевод в 0…100;
* `ci95` — **аналитическая** оценка (полуширина `1.96·15·se/2`, `se = 1/√n`), отражает только число
  доступных индикаторов, а не «истинную черту»;
* индикаторы, зависящие от аудио или рук, пропускаются, если соответствующая модальность недоступна;
* результат детерминирован: одинаковый `metrics.jsonl` → одинаковый профиль.

### Правдивость

Отдельного «детектора лжи» нет и быть не может. `psychometrics.deception_priority` даёт композитный
приор нагрузки/арузала по валидированным маркерам и вердикт «не различимо: невербальная детекция лжи
статистически незначима». Это **единственное** число правдивости во всём приложении: и датчик во вкладке
«Правдивость», и поле `score` в вердикте LLM берутся из него (раньше они расходились — 60 против 63 на
одном и том же видео). Legacy-формула конвейера осталась в `summary["truth_heuristic"]` только как
справочная величина и один из cues.

## Тесты

Офлайн-набор (быстрый, без MediaPipe, без сети и без реальных видео):

```bat
python -m unittest discover -s tests -t .
```

Покрыто: калибровка паттернов (P10D без cheek-blendshape, P12 только по yaw, P14 в речевом контексте),
геометрия касания лица (`touch_frame`, склейка и отсев эпизодов, легаси-записи), детектор морганий с
рефрактерностью, контракт слепков и детерминизм поиска, выбор паттерна по специфичности, поиск в чужом
видео (окно слепка не берётся по таймкодам источника), порог «совпадение/фон» и ответ «не найдено»,
LR-агрегация и границы интервалов, честность выводов (MBTI/эннеаграмма/PID-5), единый источник
правдивости, разбор и починка JSON от LLM, анти-галлюцинационная валидация эпизодов, приоритет
источников конфигурации, HTTP API на синтетическом прогоне (включая защиту `/file` от выхода за
каталог видео) и строгость JSON-метрик.

Тяжёлый smoke-тест с настоящим MediaPipe (нужны `models/*.task`, ~10–20 c):

```bat
set PERSONASCOPE_ENGINE_TEST=1 && python -m unittest discover -s tests -t .
```

### Оценка качества на разметке

Разметка касаний лежит в `tools/gt_touch.json` (только таймкоды, поэтому версионируется).
Прогоны для оценки кладутся в `data/gt/runs/<имя>/` (в git не попадают).

```bat
python tools/eval_touch.py            :: детектор касаний: precision/recall/F1 по кадрам и эпизодам
python tools/eval_touch.py --windows   :: что происходило внутри размеченных окон (есть ли сигнал вообще)
python tools/eval_touch.py --sweep     :: перебор порогов по уже сохранённым каналам, без MediaPipe
python tools/eval_search.py            :: поиск слепком: свой и чужой ролик, precision/recall
python tools/eval_search.py --grid     :: перебор порога «совпадение/фон» и tau
```

## Известные ограничения

* MBTI, эннеаграмма и PID-5 по видео не валидированы: это производные композиты, а не типология.
  Эннеаграмма и PID-5 намеренно возвращаются как `not_assessed`.
* Невербальные маркеры Big Five дают умеренные корреляции — этого недостаточно для индивидуального
  диагноза; шкалы стоит читать как гипотезы с открытыми формулами и интервалами.
* Качество вывода падает при плохом свете, перекрытом лице, отсутствии звука (индикаторы речи и голоса
  просто пропускаются, шкала помечается как частичная).
* `stride` ускоряет анализ, но прореживает кадры, поэтому очень короткие события (доли секунды) могут
  не попасть в выборку. Сравнение показало, что отказ от прореживания не улучшает итог, а лишь
  замедляет анализ, поэтому по умолчанию оставлено прореживание.
* **Поиск по слепку чувствителен к качеству шаблона.** Если в окне слепка кисть видна не во всех
  кадрах, шаблон «размывается», и порог «совпадение / фон» отсекает даже верные кандидаты: ложных
  находок нет, но часть реальных касаний не находится. Что делать дальше (по убыванию эффекта):
  строить шаблон только по кадрам с реально измеренным сигналом, сопоставлять не скалярные каналы,
  а нормализованные ландмарки (лицо-центричная система: начало — переносица, масштаб — межзрачковое
  расстояние), и добавить переранжирование топ-10 внешней моделью. Это следующий этап работы над
  разделом.
* Часть размеченных окон не детектируется по объективной причине: кисть вне кадра или закрыта.
  Такие эпизоды помечены в разметке типом `near` («рука рядом») и не считаются касанием — детектор
  их и не находит, что для задачи «касание лица» верно.
* Эпизоды пишутся в mp4v (OpenCV): браузер их не читает, для веба делается H.264-копия через
  `imageio-ffmpeg`. Если ffmpeg недоступен, интерфейс откроет исходный файл и предупредит.

## Дорожная карта

Работа ведётся постоянно и итеративно: следующий этап — полноценная научная оценка Big Five и MBTI
по видео. Планируется расширение карты индикаторов с опорой на мета-анализы, калибровка порогов на
размеченном корпусе (сейчас — на небольшом наборе демонстрационных роликов), оценка надёжности
(test–retest, согласие с опросниками) и явные пределы применимости MBTI вместо производных осей.
Текущее состояние — измеримая база, на которую этот этап можно надстраивать: все
пороги, формулы и доказательства уже вынесены в данные и проверяются тестами.

Отдельно по поиску эпизодов: пункты из «Известных ограничений» — шаблон из надёжных кадров,
сопоставление по ландмаркам, переранжирование топ-10 (в том числе внешней vision-моделью, если
на вашем endpoint есть модель, понимающая изображения).

## Дисклеймер

Инструмент выдаёт операциональные поведенческие оценки по видео и не является клиническим диагнозом,
психологическим заключением или средством установления правдивости. Числовые оценки — гипотезы с
открытыми формулами и интервалами, а не измеренные свойства личности.
