# PersonaScope

Поведенческий анализ видео: локальный движок MediaPipe измеряет мимику, позу, руки и речь по кадрам,
детерминированный психометрический слой переводит измерения в шкалы, внешняя LLM пишет текстовую
интерпретацию. Все числа считаются локально и воспроизводимо — модель не имеет права их менять.

```
видео ─► MediaPipe (лицо/поза/руки) + аудио-просодия ─► metrics.jsonl (по кадрам)
      ─► паттерны P01–P14 ─► эпизоды со скрин-кадрами
      ─► psychometrics.py: LR-агрегация Big Five, CI, композиты ─► summary.json
      ─► scoring.py: единый набор чисел для UI, LLM и экспорта
      ─► LLM (опционально): текстовая интерпретация + цитаты эпизодов
```

## Честный статус научной валидности

Это измерительный инструмент, а не диагностика. Что подтверждено, а что нет — зафиксировано в коде
(`psychometrics.MODEL_VALIDITY`) и выводится в интерфейсе:

| Модель | Статус по видео | Как выдаётся |
|---|---|---|
| Big Five (OCEAN) | частичная валидность невербальных маркеров (r ≈ 0.1–0.35) | LR-агрегация по индикаторам, 95 % интервал, кадры-доказательства |
| HEXACO | слабая | производные от OCEAN, помечены как низкая поддержка |
| Temperament | низкая | композит «энергия × стабильность» |
| MBTI | **не валидирован** | производные оси (S/N копируется с Openness, T/F — с Agreeableness), в ответе стоят предупреждения |
| Эннеаграмма | **не валидирована** | `status: not_assessed`, тип не выводится |
| PID-5 (DSM-5) | **неприменим** по видео | `status: not_assessed` |
| Правдивость | недиагностична (d ≈ 0.06–0.2, точность ≈ 54 %) | приор нагрузки/арузала с явной формулировкой «не различимо», НЕ вероятность лжи |

## Быстрый старт

Требования: Python 3.9–3.13 (проверено на 3.13.1 + mediapipe 1.0.0), Microsoft Visual C++ Redistributable
2015–2022 (x64) на Windows. Системные OpenGL-библиотеки **нужны только на headless Linux** — на Windows и
macOS их не существует, ставить `libEGL`/`apt-get` там нечего.

```bat
:: Windows
cd C:\PersonaScope
python run.py
```

```bash
# Linux / macOS
cd ~/PersonaScope
python run.py
```

`run.py` сам проверит зависимости (и доустановит их из `requirements.txt`, если чего-то нет), на headless
Linux при необходимости поставит mesa-пакеты, поднимет сервер и напечатает адрес.

Вручную, если автоустановка не сработала:

```bat
py -3.13 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python run.py
```

### Адрес, порт, хост

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `8008` (Windows), `8000` (Linux/macOS) | порт сервера |
| `HOST` | `127.0.0.1` | интерфейс прослушивания |

По умолчанию сервер доступен **только с этой машины**: в приложении нет авторизации, а в каталоге данных
лежат видео людей и настройки LLM. `HOST=0.0.0.0` открывает его в локальной сети (ключ LLM при этом
нелокальным клиентам всё равно не отдаётся, но видео и результаты становятся доступны).

### Модели MediaPipe

Нужны три файла в `models/` — они уже в репозитории:

```
models/face_landmarker.task   models/pose_landmarker.task   models/hand_landmarker.task
```

Если файлов нет, скачайте официальные `.task` из MediaPipe Models

## Настройка LLM (опционально)

Локальный анализ работает без интернета и без ключа. LLM нужна только для текстовой интерпретации.

Ключ можно задать тремя способами (приоритет сверху вниз):

1. **Переменные окружения:** `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TEMPERATURE`, `LLM_TIMEOUT`.
2. **Файл `.env.local`** в корне проекта (в `.gitignore`, в git не попадёт):

   ```ini
   LLM_BASE_URL=https://api.example.com/v1
   LLM_API_KEY=sk-...
   LLM_MODEL=my-model
   LLM_TEMPERATURE=0.3
   LLM_TIMEOUT=180
   ```
3. **Интерфейс:** вкладка «Настройки LLM» → сохраняется в `data/llm_config.json` (этот файл тоже
   в `.gitignore`, потому что содержит ключ).

Кнопка «Проверить» делает реальный запрос; вкладка «Промпт» показывает RAW-ответ модели. Если модель
вернула не-JSON, результаты **не применяются** — в интерфейсе появится предупреждение и RAW для разбора.

## Что именно измеряется

### Паттерны P01–P14

Пороги живут в `pipeline.PATTERN_DEFS` и калиброваны на референсных прогонах; значения и обоснование
попадают в `summary["calibration"]` каждого видео, чтобы их можно было проверить, а не принимать на веру.

| Код | Что это | Порог / определение |
|---|---|---|
| P01 | моргание | `eyeBlink > 0.5`, события с рефрактерностью 0.2 c (Doughty 1989) |
| P02 | кивок при слушании | `|pc| > 0.08` |
| P03 | движения головы | `|yc| + |pc| > 0.03` |
| P04 / P05 | жестовый эпизод / амплитуда | `hand_speed > 0.03` / `> 0.1` |
| P06 | рука около лица (адаптор) | кончик пальца в боксе лица ×1.30 **или** 3D-дистанция запястье→голова < 0.8 ширин плеч, и кисть детектирована |
| P07 | мелкая моторика (fidgeting) | `hand_speed > 0.01` |
| P08 | положение рук | `aperture < 0.8` |
| P09 | смена позы | `menergy > 0.02` |
| P10 | улыбка | `smile > 0.4` |
| P10D | Duchenne-улыбка (AU6+AU12) | `smile > 0.35` и AU6 > 0.15, где AU6 = max(`cheekRaise`, геометрия глаза) |
| P11 | напряжение мимики (AU4/AU24) | `browDown > 0.3` или `press > 0.2` |
| P12 | отведение взгляда | `|yaw − медиана| > 25°` (только yaw; кивок по pitch не учитывается) |
| P13 | вокализация | флаг речи из VAD |
| P14 | пауза в речи | тишина 0.5–3 c, начавшаяся не позже 5 c после речи |

Три порога изменены относительно прежних версий — по замерам на референсных видео:

* **P10D** раньше требовал `cheekRaise > 0.15`, но в mediapipe 1.0.0 этот blendshape равен 0.0 во всех
  кадрах (min = p50 = p90 = p99 = max = 0), поэтому паттерн не срабатывал ни разу. Теперь AU6 берётся
  как максимум из blendshape и геометрической оценки по точкам глаза (одна реализация —
  `pipeline.ocu_from_landmarks`).
* **P12** с порогом 35° давал 0–4 кадра из 1153 (0.2–0.5 %); на 25° — 1–2 %, это измеримый диапазон.
  Одновременно убран pitch: кивок — не отведение взгляда.
* **P14** считался активным на 46–94 % кадров, потому что «паузой» становилась любая тишина. Теперь
  учитывается только пауза внутри речевого контекста.

### Психометрический слой (`psychometrics.py`)

Поведенческие переменные (частота моргания, Duchenne-доля, доля негативной экспрессии, мобильность головы,
темп речи, паузы, вариабельность F0, кинетизм…) превращаются в шкалы через карту отношений правдоподобия:

* каждый индикатор даёт `LR = P(индикатор | высокая черта) / P(индикатор | низкая черта)` в диапазоне `[1/8, 8]`;
* веса зависят от уровня доказательности (`strong`/`moderate`/`weak` = 1.0/0.6/0.3);
* агрегация — нормированная сумма логарифмов LR, перевод в 0…100;
* `ci95` — **аналитическая** оценка (полуширина `1.96·15·se/2`, `se = 1/√n`), отражает только число
  доступных индикаторов, а не «истинную черту»;
* индикаторы, зависящие от аудио или рук, пропускаются, если соответствующая модальность недоступна;
* результат детерминирован: одинаковый `metrics.jsonl` → одинаковый профиль.

### Правдивость

Отдельного «детектора лжи» нет и быть не может. `psychometrics.deception_priority` даёт композитный
приор нагрузки/арузала по валидированным маркерам и вердикт «не различимо: невербальная детекция лжи
статистически незначима». Это **единственное** число правдивости во всём приложении: и датчик во вкладке
«Правдивость», и поле `score` в вердикте LLM берутся из него (раньше они расходились — 60 против 63 на
одном и том же видео). Legacy-формула конвейера осталась в `summary["truth_heuristic"]` только как
справочная величина и один из cues.

## HTTP API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/videos` | загрузка видео |
| `POST` | `/api/videos/{id}/analyze?stride=&width=` | запуск анализа в фоне |
| `GET` | `/api/jobs/{id}` | прогресс фонового анализа |
| `GET` | `/api/videos/latest` | последний завершённый анализ |
| `GET` | `/api/videos/{id}/summary` \| `/metrics` \| `/truth` \| `/scores` | результаты |
| `GET` | `/api/videos/{id}/file?path=` | кадры, клипы, дашборд (только внутри каталога видео) |
| `POST` | `/api/videos/{id}/snapshots` \| `/search` | цифровой слепок жеста и поиск похожих эпизодов (z-norm + DTW) |
| `GET`/`PUT` | `/api/llm/config`, `GET /api/llm/status`, `POST /api/llm/test` | настройки LLM |
| `POST` | `/api/videos/{id}/llm/analyze`, `GET .../llm/status` | фоновый LLM-анализ |
| `GET` | `/api/videos/{id}/report/pptx` | отчёт PowerPoint |

Ключ LLM отдаётся только клиентам с этой же машины; менять настройки LLM можно тоже только локально.

## Данные и приватность

```
data/<video_id>/
  source.mp4            исходное видео
  source_web.mp4        H.264-копия для браузера (ffmpeg)
  metrics.jsonl         кадровые метрики — строгий JSON (NaN/Infinity → null)
  summary.json          паттерны, эпизоды, калибровка, психометрический слой
  llm_result.json       RAW + разобранный ответ LLM (если анализ запускался)
  dashboard.mp4         видео с графиками
  episodes/*.jpg|mp4    кадры-доказательства и клипы эпизодов
  report.pptx           отчёт (по запросу)
data/index.json         реестр завершённых прогонов (записи без каталога отбрасываются)
data/snapshots/*.json   цифровые слепки
```

Каталог данных можно вынести в другое место: `PERSONASCOPE_DATA=D:\ps_data`.

В git не попадают: `data/`, `data_test/`, `Downloads/`, `*.mp4`, `*.jsonl`, `*.pptx`, `*llm_config.json`,
`.env*`, `__pycache__/`, `.venv/`. **Ключи и видео людей коммитить нельзя** — если файл уже был в индексе
до добавления в `.gitignore`, снимите его отдельно: `git rm --cached data/llm_config.json`.

## Тесты

Офлайн-набор (53 теста, ~0.3 c, без MediaPipe, без сети, без реальных видео):

```bat
python -m unittest discover -s tests -t .
```

Покрыто: калибровка паттернов (P10D без cheek-blendshape, P12 только по yaw, P14 в речевом контексте),
детектор морганий с рефрактерностью, контракт слепков и детерминизм поиска, LR-агрегация и границы
интервалов, честность выводов (MBTI/эннеаграмма/PID-5), единый источник правдивости, разбор и починка
JSON от LLM, анти-галлюцинационная валидация эпизодов, приоритет источников конфигурации, HTTP API на
синтетическом прогоне (включая защиту `/file` от выхода за каталог видео) и строгость JSON-метрик.

Тяжёлый smoke-тест с настоящим MediaPipe (нужны `models/*.task`, ~10–20 c):

```bat
set PERSONASCOPE_ENGINE_TEST=1 && python -m unittest discover -s tests -t .
```

## Известные ограничения

* MBTI, эннеаграмма и PID-5 по видео не валидированы: это производные композиты, а не типология.
  Эннеаграмма и PID-5 намеренно возвращаются как `not_assessed`.
* Невербальные маркеры Big Five дают корреляции r ≈ 0.1–0.35 — этого мало для индивидуального диагноза.
* Качество вывода падает при плохом свете, перекрытом лице, отсутствии звука (индикаторы речи и голоса
  просто пропускаются, шкала помечается как частичная).
* `stride` ускоряет анализ, но прореживает кадры: детекторы морганий и жестов становятся грубее.
* Эпизоды пишутся в mp4v (OpenCV): браузер их не читает, для веба делается H.264-копия через
  `imageio-ffmpeg`. Если ffmpeg недоступен, интерфейс откроет исходный файл и предупредит.

## Дорожная карта

Следующий этап — полноценная научная оценка Big Five и MBTI по видео: расширение карты индикаторов с
опорой на мета-анализы, калибровка порогов на размеченном корпусе (а не на трёх референсных роликах),
оценка надёжности (test–retest, согласие с опросниками), явные пределы применимости MBTI вместо
производных осей. Текущее состояние — измеримая база, на которую этот этап можно надстраивать: все
пороги, формулы и доказательства уже вынесены в данные и проверяются тестами.

## Дисклеймер

Инструмент выдаёт операциональные поведенческие оценки по видео и не является клиническим диагнозом,
психологическим заключением или средством установления правдивости. Числовые оценки — гипотезы с
открытыми формулами и интервалами, а не измеренные свойства личности.
